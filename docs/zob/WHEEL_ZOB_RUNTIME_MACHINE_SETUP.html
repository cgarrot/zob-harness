Installation and operations

Wheel ZOB Runtime: machine-by-machine setup

Use this guide to install and validate the Wheel ZOB pack on a primary workstation, additional trusted machines, and a non-interactive CI host while preserving the current provider-backed run/start no-ship boundary.

PlanFleet validation and deterministic mission planning
Run in PiImplemented command shapes; operational source-edit use is currently blocked
0 effectsValidation, preview, simulation, and disabled/fake supervision only
No daemonEach trusted checkout operates independently
Distribution blocker

The implementation is currently in an uncommitted working tree. The current machine can validate, preview, and run disabled/deterministic-fake checks, but another machine cannot clone this exact runtime until the changes receive review and an explicitly authorized governed commit, push, or release tag.

Current capability boundary

What works now

  • Fleet v5 story validation
  • Deterministic public mission previews
  • Six functional model pools
  • Full in-memory factory simulation
  • Implemented Pi /wheel-zob run and run-machine shapes, operationally blocked pending source/workspace enforcement
  • Durable hash-chained disabled/fake scheduling, recovery, model-role, workspace/PR/CI, and PR-close validation
  • Terminal CLI, including plan-machine and supervisor-plan|init|run-fake|status|validate|resolve-human

What does not work yet

  • No enforced active-workspace source equality or transition-time workspace/branch/HEAD reinspection
  • No machine-to-story worktree bridge or atomic pre-effect Wheel commit authority validation
  • No live jointhewheel Fleet adapter
  • No live model dispatch through role pools
  • No real application worktrees, branches, PRs, Checks, merges, or deployment
  • No production daemon or live shared supervisor

4 · operator-01

Set up the primary workstation

  1. Install the trusted checkout

    cd /path/to/zob-harness
npm ci
npm run doctor:wheel-zob

    Use npm ci, not npm install. A passing source doctor reports valid=true and externalEffectsEnabled=false. It does not require provider tools or inspect authentication.

  2. Optionally install Fireconnect for Fireworks use

    Skip this step for Wheel validation, planning, disabled initialization, deterministic-fake supervision, and simulation. Those operations do not call providers.

    export FIRECONNECT_COMMIT="977855aa082bcb7a696b43bc34226d5ff11d0eb1"
git clone https://github.com/fw-ai/fireconnect.git "$HOME/.fireconnect/cli" && \
  git -C "$HOME/.fireconnect/cli" checkout --detach "$FIRECONNECT_COMMIT" && \
  test "$(git -C "$HOME/.fireconnect/cli" rev-parse HEAD)" = "$FIRECONNECT_COMMIT" && \
  bash "$HOME/.fireconnect/cli/install.sh" && \
  export PATH="$HOME/.local/bin:$PATH" && \
  fireconnect --version

    The command chain fails closed: the installer cannot run if clone, checkout, or immutable commit verification fails. Expected version: v0.8.0.

  3. Optionally authenticate Fireworks

    fireconnect login
fireconnect pi on
fireconnect pi status

    Use the guided browser/key prompt. Never paste an API key into the repository or shared chat. Do not copy ~/.fireconnect/, Pi auth files, or keychain data between machines.

    export WHEEL_ZOB_FIRECONNECT_BIN="$(type -P fireconnect)"
npm run doctor:wheel-zob -- --providers

    To restore Fireconnect’s saved Pi configuration, run fireconnect pi off.

  4. Install interactive Pi and authenticate OpenAI Codex

    npm install --global @earendil-works/pi-coding-agent@0.80.7
export WHEEL_ZOB_PI_BIN="$(type -P pi)"
"$WHEEL_ZOB_PI_BIN" --version
cd /path/to/zob-harness
"$WHEEL_ZOB_PI_BIN"

    Inside Pi, run /login, select ChatGPT Plus/Pro (Codex), and complete OAuth. Then use /model to choose openai-codex/gpt-5.6-sol and set thinking to high.

    "$WHEEL_ZOB_PI_BIN" --provider openai-codex --model gpt-5.6-sol --thinking high

  5. Run the interactive/provider-aware doctor

    WHEEL_ZOB_PI_BIN="$(type -P pi)" \
WHEEL_ZOB_FIRECONNECT_BIN="$(type -P fireconnect)" \
npm run doctor:wheel-zob -- --interactive --providers

    The Pi path must be absolute and outside the repository. Authentication remains a separate explicit status/login check.

  6. Trust and load project extensions

    cd /path/to/zob-harness
WHEEL_ZOB_PI_BIN="$(type -P pi)"
"$WHEEL_ZOB_PI_BIN"

    Review the checkout before approving project trust. Inside Pi, run:

    /reload
/wheel-zob pools

    The manifest loads the ZOB switch, ZOB harness, and Wheel ZOB extension bridges.

  7. Run the full validation ladder

    npm run doctor:wheel-zob
npm run check -- --pretty false
npm run validate:wheel-zob-model-registry
npm run validate:wheel-zob-fleet-v5
npm run smoke:wheel-zob-pack
npm run smoke:wheel-zob-extension
npm run wheel-zob -- simulate installation-check
npm test
    source "$HOME/.venvs/wheel-zob-docs/bin/activate"
python3 docs/zob/validation/validate_contracts.py
python3 docs/zob/validation/validate_documentation.py

    Stop if any command fails.

5 · Safe operation

First use: exact commands

Inspect model pools

npm run wheel-zob -- pools
/wheel-zob pools

Validates static routing. It does not call a provider.

Validate a Fleet story

npm run wheel-zob -- validate \
  docs/zob/examples/story-execution.example.json
/wheel-zob validate docs/zob/examples/story-execution.example.json

Preview a mission

npm run wheel-zob -- plan demo-mission \
  docs/zob/examples/story-execution.example.json
/wheel-zob plan demo-mission docs/zob/examples/story-execution.example.json

Public output contains commitments/hashes, not protected route identities. Dispatch remains disabled.

Simulate the lifecycle

npm run wheel-zob -- simulate demo-mission
/wheel-zob simulate demo-mission

Expected stages: Story needs-review, Blind Review clean, Staging complete, Assurance passed, Promotion complete.

Validate or preview a story set

/wheel-zob validate path/to/story.json
/wheel-zob plan <mission-id> path/to/story.json [path/to/dependency.json ...]
Provider-backed story run is operationally blocked

/wheel-zob run is implemented but queues a Pi model turn that can invoke the selected provider, incur spend, and edit the active checkout. Do not execute it for an operational story until active-workspace source equality and transition-time workspace/branch/HEAD reinspection are enforced and independently reviewed.

Preview one explicit source-bound machine assignment

npm run wheel-zob -- plan-machine \
  <mission-id> <machine-id> path/to/machine-bundle.json

The preview validates source and bundle hashes, every machine/story assignment, every story manifest, dependencies, and cycles before selection. It starts no agent turn.

Provider-backed machine run is operationally blocked

/wheel-zob run-machine is implemented but queues one provider-backed turn in the active checkout. Do not execute it until source/workspace enforcement is implemented, negative-tested, and independently reviewed. Commit, push, GitHub mutation, merge, promotion, and deployment also remain unavailable.

Run the durable activation-disabled supervisor

npm run wheel-zob -- supervisor-plan <mission-id> path/to/machine-bundle.json
npm run wheel-zob -- supervisor-run-fake \
  <mission-id> path/to/machine-bundle.json \
  reports/wheel-zob/supervisor/<mission-id>
npm run wheel-zob -- supervisor-status reports/wheel-zob/supervisor/<mission-id>
npm run wheel-zob -- supervisor-validate reports/wheel-zob/supervisor/<mission-id>

This persists a body-free journal/checkpoint and exercises development, QA, repair, blind review, fake workspace/PR/CI, and PR-close loops with zero provider, network, credential, repository, or GitHub effects. Restart with the exact same mission, bundle, and state directory. Human gates require an explicit hash-only receipt.

See the durable disabled supervisor runbook for stop, restart, ownership recovery, rollback posture, and the live-activation stop.

Required simulation posture

activationEnabled=false, externalEffects=false, githubWrites=false, merge=false, workflowDispatch=false, deployment=false, and providerActivation=false.

Inputs must be reviewed, sanitized, repo-relative JSON files. Absolute paths, traversal, sessions, environment/credential/key names, and symlink escapes are intentionally blocked.

6 · worker-01 and peers

Set up additional trusted machines

Not available until release

The required reviewed commit or tag does not exist for the current uncommitted runtime. Do not clone origin/main and assume it contains this implementation.

After a reviewed commit/tag exists:

export ZOB_REPO_URL="https://github.com/cgarrot/zob-harness.git"
export ZOB_REF="<reviewed-commit-or-tag>"
git clone "$ZOB_REPO_URL" zob-harness
cd zob-harness
git fetch --tags --prune
git checkout --detach "$ZOB_REF"
git rev-parse HEAD
npm ci
npm run doctor:wheel-zob
  • Record the exact commit; every machine must report the same value.
  • CLI-only validation and simulation require no provider login.
  • Repeat provider authentication locally only when that user needs it.
  • Never transfer credentials from operator-01.
  • Run the full operator validation ladder.

For interactive use, install Pi 0.80.7, launch its absolute path from repository root, approve trust after review, run /reload, then verify /wheel-zob pools and /wheel-zob simulate worker-check.

8 · No-ship boundary

Do not install a live staging or production runtime

There is no approved procedure for using this pack as a live service.

  • Do not create a zobd service.
  • Do not provision GitHub Apps.
  • Do not create or protect develop-staging because of this pack.
  • Do not enable automatic merges or deployment credentials.
  • Do not convert simulation transitions into real effects.
  • Do not share provider credentials with a service account.

A future live phase requires application adapters, durable state/checkpoints, least-privilege credentials, branch/CI integration, rollback evidence, pilots, and a fresh independent oracle review.

12 · Diagnostics

Troubleshooting

/wheel-zob is unknown
  1. Confirm repository root.
  2. Run npm ci and npm run doctor:wheel-zob.
  3. Confirm package.json lists the Wheel extension bridge.
  4. Confirm global Pi is 0.80.7 and launch that absolute executable from repository root.
  5. Review and trust the project.
  6. Run /reload.
fireconnect is not found or inactive
export PATH="$HOME/.local/bin:$PATH"
fireconnect --version
fireconnect login
fireconnect pi on
fireconnect pi status

Restart Pi after configuration changes. If installation is missing, rerun only the pinned, fail-closed §4 installer.

OpenAI Codex is unavailable

Inside Pi, run /login, choose ChatGPT Plus/Pro (Codex), complete OAuth, then use /model to select openai-codex/gpt-5.6-sol.

Doctor fails on Node
nvm use 22.22.3
node --version
npm ci
npm run doctor:wheel-zob
A story path is rejected

The file must be a normal repo-relative file inside the trusted checkout. Absolute paths, traversal, private sessions, environment/credential/key names, and symlink escapes are blocked intentionally.

Mission preview has no model identities

Expected behavior. Public output stores route commitments/hashes rather than protected model identities.

Simulation or fake supervision completes but GitHub does not change

Expected behavior. The runtime has only disabled/deterministic-fake GitHub-effect brokers and all external effects remain false.
